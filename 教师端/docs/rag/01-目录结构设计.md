# 01 知识库整体目录结构设计

## 目标
为「教育智能体教师端」提供一套企业级、可生产部署的高中全学科 RAG 知识库目录规范。要求：离线可用、可增量更新、可审计、可打包分发，并与既有 FastAPI 后端（`app/`）干净解耦。

## 顶层目录

```
教师端/
├── backend/
│   ├── server.py                 # FastAPI 入口；挂载 /rag 路由 + 注册异步构建执行器
│   ├── requirements.txt          # 依赖清单（含 RAG 检索层依赖）
│   └── app/
│       ├── api.py                # 既有业务 API（会话/任务/模型/知识库）
│       ├── kb.py                 # 知识库检索服务：RAG 优先，失败回退旧子串匹配
│       └── rag/                  # ★ RAG 检索层（模块内高内聚）
│           ├── __init__.py       # 模块导出
│           ├── config.py         # 全部参数/路径/学科常量（环境变量可覆盖）
│           ├── schema.py         # 数据模型：KnowledgeNode / Document / Chunk / Retrieval*
│           ├── models.py         # Embedder / Reranker 懒加载（ONNX 首选，mock 兜底）
│           ├── bm25.py           # jieba 分词 + BM25Okapi 倒排索引（可 pickle 落盘）
│           ├── vector_store.py   # sqlite-vec 向量库封装（vec0 虚拟表）
│           ├── chunker.py        # 分块器（知识树叶子为原子单元 + 重叠）
│           ├── reranker.py       # 重排薄封装（bge-reranker，不可用则原序）
│           ├── hybrid.py         # ★ 混合检索编排（学科路由→改写→双路召回→RRF→重排）
│           ├── pipeline.py       # 索引构建与生命周期（断点续建 + manifest）
│           └── api_router.py     # /rag/status、/retrieve、/subjects、/build
├── scripts/
│   ├── clean_corpus.py           # 语料清洗与标注（M3）
│   ├── validate_tree.py          # 知识树结构校验（M2）
│   ├── build_index.py            # 索引构建命令行入口（M4）
│   ├── evaluate.py               # QA 评测（Recall/MRR/负例误召回）（M6）
│   ├── export_onnx.py            # 模型导出 ONNX + int8 量化（M7）
│   └── package_models.py         # 模型离线包打包（zip + SHA256）（M7）
├── rag_data/                     # ★ 运行时数据（Electron 可注入 RAG_DATA_ROOT 覆盖）
│   ├── knowledge-tree/           # 九学科知识树 {学科}.json（M2）
│   ├── raw/                      # 原始语料（不入库，清洗后进 corpus）
│   ├── corpus/                   # 清洗后文本 corpus/{学科}/*.txt（M3）
│   ├── chunks/                   # 分块落盘 chunks/{学科}.jsonl（M4）
│   ├── index/                    # 向量库 kb_vec.sqlite + bm25_index.pkl + manifest.json（M4）
│   ├── models/                   # ONNX embedding/reranker（离线分发，M7）
│   ├── models-pack/              # 模型离线安装包（zip + sha256，M7）
│   └── logs/                     # 清洗报告 / 运维日志
├── tests/rag/qa/                 # 每科 50 条 QA 评测集 {学科}.json × 9（M6）
└── docs/rag/                     # ★ 交付文档（本文档系列 M1~M7）
```

## 设计决策

1. **数据与代码分离**：`rag_data/` 独立于 `backend/app/rag/`，生产可整体挂载/替换，便于离线分发与多实例隔离。
2. **路径可覆盖**：`config.py` 内所有路径支持 `RAG_DATA_ROOT` / `RAG_MODEL_DIR` 环境变量覆盖，适配 Electron 注入的真实数据目录。
3. **分层职责**：`retrieve`（kb.py）→ `hybrid.search`（编排）→ `vector_store`/`bm25`/`reranker`（能力）→ `chunker`/`pipeline`（构建），各层单测可独立替换。
4. **降级优先**：模型缺失时 embedding 走确定性 mock、rerank 禁用、索引为空时 kb.py 自动回退旧子串匹配，保证服务永不因 RAG 故障而不可用。
5. **断点续建**：`chunks/{学科}.jsonl` 按 chunk hash 判断是否重算 embedding，支持增量/断点重建。

## REST 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/rag/status` | 索引状态 / 块数 / 模型加载 / 参数 |
| GET | `/rag/retrieve` | 混合检索（subject/topic/top_n/history） |
| GET | `/rag/subjects` | 九学科列表 |
| POST | `/rag/build` | 异步索引构建（task_queue + SSE 进度） |
| GET | `/api/kb/retrieve` | 业务层检索（RAG 优先，兼容旧前端） |
