# 05 检索链路设计

## 整体流程（`hybrid.search`）

```
请求(query, subject?)
  ├─ 学科自动路由 route_subject()          按显式指定 + 关键词命中
  ├─ 查询改写 rewrite_query()              多轮上下文指代消解（它/该/此→主题词）
  ├─ ① 向量召回 vector_store.knn()          sqlite-vec，按学科过滤
  ├─ ② 关键词召回 bm25.search()             jieba 分词 + BM25Okapi，按学科过滤
  ├─ ③ RRF 融合 _rrf()                       Reciprocal Rank Fusion
  ├─ ④ 重排 reranker.rerank()               bge-reranker（不可用则原序）
  ├─ ⑤ 阈值过滤 + 沿知识树补父链上下文
  └─ 组装 RetrievalResult（hits + context + sources）
```

## 关键设计

### 1) 学科自动路由
`_SUBJECT_KEYWORDS` 为每科配置领域关键词，按命中次数加权（学科名命中权重 +2），返回得分最高学科。显式 `subject` 参数优先。用于：
- 按学科过滤召回（`SUBJECT_FILTER`，默认开启），避免跨科串扰；
- 结果上下文标注路由学科。

### 2) 查询改写
离线无 LLM 场景下的轻量改写：若查询含`它/该/此/上述/这个/那个`等指代词，且上一轮历史存在，则取上一轮最长名词片段替换，实现多轮指代消解。

### 3) 双路召回
- **向量**：`sqlite-vec` vec0 表 KNN，`VECTOR_TOP_K=50`，语义召回。
- **关键词**：`BM25Okapi`，`BM25_TOP_K=30`，专有名词/公式/精确术语召回。
- **mock 向量降级**：当 embedding 走确定性 mock（无真实模型）时，因其 hash 向量无语义区分度，**跳过向量召回**，仅用关键词召回，避免污染 RRF 融合（见 `hybrid.py`）。向量调用异常时自动 `reset_onnx()`，下次重载。

### 4) RRF 融合
对多路召回按 `score = Σ 1/(k+rank+1)` 融合（`RRF_K=60`），取 `FUSE_TOP_N=20` 候选。仅融合实际命中的召回器。

### 5) 重排
`bge-reranker-v2-m3`（Cross-Encoder）对 top-20 候选重排序，写 `rerank_score`。模型缺失/加载失败时原序返回（`rerank_used=False`）；加载失败仅首次尝试打日志，避免反复告警。

### 6) 阈值与上下文
- `MIN_SCORE` 之上的命中才进入结果（当前默认 0，即不设硬阈值，靠排序保证）。
- `RERANK_TOP_N=8` 为最终返回块数。
- 每条命中沿知识树补全 `模块/章/节/知识点` 父链；`context` 组装为供 LLM 注入的 `学科 + [知识点]（难度/来源）：正文` 结构，`sources` 收集去重来源清单，支持可溯源问答。

## 参数（`config.RetrievalParams`，环境变量可覆盖）

| 参数 | 默认 | 环境变量 |
|---|---|---|
| VECTOR_TOP_K | 50 | RAG_VECTOR_TOP_K |
| BM25_TOP_K | 30 | RAG_BM25_TOP_K |
| RRF_K | 60 | RAG_RRF_K |
| FUSE_TOP_N | 20 | RAG_FUSE_TOP_N |
| RERANK_TOP_N | 8 | RAG_RERANK_TOP_N |
| MIN_SCORE | 0.0 | RAG_MIN_SCORE |
| SUBJECT_FILTER | true | RAG_SUBJECT_FILTER |
| RERANK_ENABLED | true | RAG_RERANK_ENABLED |

## 业务层接入（`kb.retrieve`）

`app/kb.py` 暴露兼容旧前端的 `retrieve(subject, topic)`：
1. 若 RAG 索引非空（`rag status` 块数 > 0），走 `hybrid.search`，返回 `engine: "rag"` + 结构化 `matched_nodes`（含 kp_id/来源/难度/正文）。
2. RAG 不可用或返回空时，自动回退旧 `workflow.KnowledgeBase` 子串匹配，返回 `engine: "legacy"`。
3. 前端与工作流无需改动即可获得 RAG 增强。

## REST 接口

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/rag/retrieve` | subject, topic, top_n, history | 混合检索 |
| GET | `/rag/status` | — | 索引/模型/参数状态 |
| GET | `/rag/subjects` | — | 九科学科列表 |
| POST | `/rag/build` | subjects, force | 异步构建（SSE 进度） |

`/rag/retrieve` 返回体含 `query、routed_subject、query_rewritten、rerank_used、degraded、context、sources、hits[]`，其中 `hits[]` 每项含 `chunk_id/kp_id/subject/knowledge_point/module/chapter/section/chunk_type/difficulty/level/source/text/score/rerank_score`，可直接用于高置信检索与溯源展示。
