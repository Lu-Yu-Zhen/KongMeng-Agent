## 一、改造说明

### 1.1 改造前结论（核查结果）

备课功能 Agent 模式**此前未使用 Qoder Agent SDK**：全项目无 SDK 引用（仅 `agent-core.js` 注释中提及"参考 QoderWork 编排模型"）。原链路为：前端 `backend-client.js` → 后端 `/api/tasks/workflow` → `workflow.py`（LangChain+LangGraph 意图路由＋产物注册表＋质量门）；三大板块中提问/批改甚至不经过后端（渲染进程直连模型 API）。

### 1.2 改造后架构

```
学生提问板块 ─┐                          ┌─ query_profile（伪 ID 画像）
题目批改板块 ─┼→ /api/databus/* 写入 ─→ 学情数据总线(8表) ─┼─ class_stats（班级聚合）
学情分析板块 ─┘   （记录+事件同事务）    kongmeng.db   ├─ data_usage（四板块使用情况）
                                                    └─ 审计哈希链 audit_log
                                                          ↑ 进程内 MCP 工具（只读）
备课板块（主板块·汇总调用）←── /api/agent/lesson_prep ────┘
        引擎选择：Qoder Agent SDK（qodercli_auth/PAT）⇄ Mock 确定性引擎
        产物导出：复用 workflow.export_results（docx/pptx/质量检测报告）
```

### 1.4 数据共享机制（字段映射 / 时序 / 一致性）

**共享字段（三板块 → 备课统一语义）**：`pseudo_id`（伪 ID，端侧映射）、`subject`、`kp_id`（对齐 RAG 九科知识树编码）、五类错因枚举（知识/方法/计算/格式/审题）、`teacher_confirmed`、`version`、`sensitivity`。

**读写时序**：T0 写路径＝记录表＋事件表**同事务**落库；T1＝`save_*` 返回前同步消费事件（秒级画像更新，每事件一提交）；T2＝报告/备课按需聚合读（快照口径）。

**一致性保证（本次验证实证）**：
1. 单写者：profiles 仅事件消费者写，板块只产事件；
2. 幂等：event_id=type:ref 唯一，重放不重复累计；
3. 乐观锁：画像更新 `WHERE version=?`；
4. 教师权威：未确认批改不计口径（P2006 用例）；`/databus/correction` 修正事件高优先级重算；
5. **口径统一**：班级均值＝学生个体掌握率均值（修复了考试分层路径用记录级均值覆盖的双口径缺陷）；
6. **事务提交修复**：事件消费者补上每事件 commit（原实现长挂事务，跨连接不可见、进程退出丢失——验证脚本抓出的真实 bug）；
7. 审计哈希链 `prev_hash` 防篡改，`/databus/audit` 可校验。

### 1.5 备课板块如何"基于学情生成"

`lesson_prep` 强制 Agent 先调数据工具（usage→class_stats→kb），系统提示词规定：薄弱/盲区知识点必须落实为教学环节与分层作业、分层人数必须与 tierDist 一致、末尾必须输出「数据使用说明」章节（列明四板块引用条数与数据截至版本）。

### 5.2 质量硬校验（内建于工具，不达标拒绝生成并返回问题清单）

**PPT（validate_slides）**：
- ≥12 页；每个内容页要点 ≥2 条且合计 ≥60 字；案例页题干 ≥40 字；
- concept/case/summary 页必须带「总结提炼」（summary ≥15 字）——对应"每页有知识点讲解、案例说明与总结提炼"；
- 版式 ≥6 种、单一版式占内容页 ≤50%、必含图表页＋案例页＋（分栏或表格页）——对应"排版多样化"；
- 禁止占位性表述；文件体积 ≥500KB（图文质感下限）。

**教案（validate_lesson_plan）**：
- 十大板块齐备；全文 ≥3000 字；学情分析必须引用掌握率百分比等真实数据；
- 教学过程每环节 ≥80 字；禁止"略/待补充/TODO"等占位表述；逐项评分（满分 100）。

### 5.3 MCP 工具封装（Qoder Agent SDK · 进程内 server）

`backend/app/agent/export_tools.py` 新增 **`kongmeng-export` MCP server**：
- `gen_lesson_plan(markdown, topic)`：校验→docx 落盘「备课产物/」→返回路径＋评分；
- `gen_ppt(slidesJson, subject, grade)`：校验→多版式 pptx→返回路径＋版式统计；
- 校验失败返回 `isError=true`＋具体问题清单 → **真引擎在 SDK Agent 循环内自动看到失败原因并修正重试**（质量约束从"提示词软约束"升级为"工具层硬约束"）；
- 产物登记 EXPORT_REGISTRY，`/api/agent/lesson_prep` 运行结束取走并登记产物历史；旧全文输出格式保留为兜底链路。
- `qoder_agent.py`：双引擎接线（mcp_servers/allowedTools/canUseTool 扩至两个 server）；mock 引擎与真引擎调用**完全相同的生成脚本与校验**；systemPrompt 改为"读数据→gen_lesson_plan→gen_ppt→简短收尾"四步流程。
